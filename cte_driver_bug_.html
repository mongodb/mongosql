Is the CTE driver failure a real bug? YES

Short answer: the SQL is valid and executes. The failure is real, but it is not in query translation or execution — it is in a separate public API, mongosql::get_namespaces, which the JDBC driver calls before translation to learn which collection schemas to fetch. That function reports WITH-clause (CTE) names as if they were collections.

Why the existing with.yml tests still pass: those tests call mongosql::translate_sql(...), which runs the full rewrite pipeline (including CTE resolution) and then executes. They never call get_namespaces. The two are different code paths, so passing with.yml and failing get_namespaces are fully consistent.

1. The two code paths

PathUsed byHandles CTEs?
translate_sql → rewrite pipeline (WithQueryRewritePass) with.yml spec/e2e tests, query execution Yes — CTE names are resolved to derived sources
get_namespaces → get_collection_sources JDBC driver (MongoSQLTranslate.getNamespaces) to fetch schemas No — runs on the raw parsed AST

2. Evidence — get_namespaces returns CTE names

Running each query from tests/spec_tests/query_tests/with.yml through get_namespaces("spec_query_with", <query>) (before the fix):

Query (from with.yml)Namespaces returnedCTE names leaked
WITH t as (SELECT foo from biz) (SELECT * from t) {biz, t} t
WITH t as (SELECT foo, bar, car from biz JOIN baz ...) (SELECT * from t) {baz, biz, t} t
WITH t as (...biz), u as (...baz) (SELECT * from t JOIN u ...) {baz, biz, t, u} t, u
WITH t as (...biz WHERE ...), u as (...bar WHERE ...) (SELECT ...) {bar, biz, t, u} t, u

t and u are CTE names, not collections. Every query in with.yml leaks them.

Bottom line: the driver is behaving correctly — it faithfully asks for a schema for every namespace the translator reports, and refuses to proceed when one is missing. The extra namespace is introduced by mongosql::get_namespaces, which is why the fix belongs in the translator (step 6), not the driver.

4. Root cause

  • get_namespaces — mongosql/src/lib.rs:134 — parses the SQL and calls ast::visitors::get_collection_sources directly on the parsed AST.
  • get_collection_sources — mongosql/src/ast/visitors/collections.rs:14 — walks the AST and collects every CollectionSource node. A CTE reference (FROM t) is syntactically a collection datasource, so it is collected too.
  • CTE names are only turned into derived sources by WithQueryRewritePass (mongosql/src/ast/rewrites/with_query.rs), which the full translate_sql pipeline runs but get_namespaces does not.

So the bug is: namespace extraction runs before CTE resolution.

5. Fix

Apply WithQueryRewritePass before collecting collection sources, in mongosql/src/lib.rs:

pub fn get_namespaces(
    current_db: &str,
    sql: &str,
) -> Result<BTreeSet<agg_ast::definitions::Namespace>> {
    use ast::rewrites::Pass;

    let ast = parser::parse_query(sql)?;
    // Resolve `WITH` clause references before collecting collection sources. Otherwise CTE
    // names (which are not collections) are reported as namespaces, causing consumers such
    // as the JDBC driver to fail while trying to fetch a schema for a non-existent collection.
    let ast = ast::rewrites::WithQueryRewritePass.apply(ast)?;
    let namespaces = ast::visitors::get_collection_sources(&ast)
        .into_iter()
        .map(|cs| agg_ast::definitions::Namespace {
            database: cs.database.unwrap_or_else(|| current_db.to_string()),
            collection: cs.collection,
        })
        .collect();
    Ok(namespaces)
}

For non-WITH queries the pass is a no-op (the visitor returns the query unchanged), so behaviour is otherwise identical. The existing test_get_namespaces suite plus two new regression tests cover it:

  • with_clause_excludes_cte_names
  • with_clause_multiple_ctes

7. Notes / follow-ups

  • The driver-side failure is a consequence of this translator behaviour, not a separate driver bug.
  • Consider adding a get_namespaces case to the CTE spec-test coverage so this path is exercised — the existing with.yml tests only cover translate_sql.
